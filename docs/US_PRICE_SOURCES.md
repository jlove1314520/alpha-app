Yahoo 回的是 `possibly delisted; no timezone found`——這是它對已下市代號的標準回應，

**宇宙與價格必須同時是 survivorship-free 才有意義，只修一邊等於沒修。**

## 二、Stooq 三來源查證

依紀律要求涵蓋 4 類來源中的至少 3 類。

### （1）官方網站直接實測
| 端點 | 結果 |
|---|---|
| `https://stooq.com/q/d/l/?s=aapl.us&i=d` | HTTP **200 但回 HTML**，內容是 JS 工作量證明驗證頁 |
| `https://stooq.com/q/l/?s=aapl.us&f=...&e=csv` | HTTP **404** |
| `https://stooq.pl/q/d/l/?s=aapl.us&i=d`（波蘭原始域名） | 同樣的 JS 驗證頁 |

驗證頁內容：要求瀏覽器用 `crypto.subtle.digest` 對一個 challenge 字串反覆 SHA-256，
湊出 4 個前導零的雜湊，再 POST 到 `/__verify`。

**注意這是「200 + HTML」**，跟 CLAUDE.md 已知地雷裡 `openapi.twse.com.tw` 的陷阱一模一樣。
只看狀態碼會誤判成成功。

### （2）GitHub／社群
pandas-datareader issue #1012「Stooq now requires API key - Documentation update needed」
（2026-04 開立）：`pandas_datareader.DataReader` 對 Stooq 失敗並拋 `ParserError`，
因為 Stooq 回的是「請申請 API key」的 HTML 而不是 CSV。
→ https://github.com/pydata/pandas-datareader/issues/1012

這條證實了**不是我們被個別封鎖，是 Stooq 在 2026 年 3 月改了存取模式**。

### （3）其他供應商／第三方說明
多方資料一致指出：Stooq 資料**本身免費、沒有訂閱費**，涵蓋 21,000＋ 全球標的、
數十年歷史；2026 年起存取需 API key，**key 經由網站上的 CAPTCHA 取得**，
並有每日請求額度上限（超過回 `Exceeded the daily hits limit`）。

## 三、取得方式鐵律怎麼適用（重要，別誤讀）

我**有能力**用幾行 Python 解掉那個 SHA-256 工作量證明。**沒有做，也不准做。**
鐵律列舉的禁止形式包含「解驗證碼」「換 IP 或加代理規避速率限制」，
且寫明「不論是否對外使用——自用、研究、只跑一次通通不算例外」。

**但這不代表 Stooq 出局。** 要分清楚兩件事：

- ❌ **程式自動解掉 CAPTCHA／PoW 拿資料** = 繞過，禁止。
- ✅ **人到官網用正常流程過一次 CAPTCHA、領一把官方發的免費 key** = 走官方途徑，
  正是鐵律要求的「只走官方 API 與文件」。

所以正確做法不是硬取，也不是放棄，而是**請總司令親自領一次 key**。
這件事我不能代勞：代勞就等於自動解 CAPTCHA。

**教訓（跟本檔前面 Cowork 的 `tail4c7XXXX` 佔位符事故同一類）**：
沒有親自看到的畫面，不要寫成逐步操作指南。

**不要寫成看起來可以照做的步驟**。使用者照著做失敗時，
會先懷疑自己做錯，而不是懷疑指南本身。

## 一、總司令裁示要的那個數字：兩來源收盤差異率

**AAPL，AV 與 yfinance 共同日期 100 筆：**

| 指標 | 數值 |
|---|---|
| 平均相對差異 | **0.0000%** |
| 最大相對差異 | **0.0000%** |
| 差異 > 0.1% 的日數 | **0 / 100（0.0%）** |

**兩來源對同一 ticker 同一日收盤完全一致。** 交叉驗證這一項成立。

## 二、已下市股覆蓋：形式上 3/4，實質上 2/4

| 標的 | 結果 | 判定 |
|---|---|---|
| **TWTR** | 100 筆，**結束於 2022-10-28**，末收 **53.70** | ✅ **正確**——正是馬斯克收購完成下市日，貼近 54.20 收購價 |
| **ATVI** | 100 筆，**結束於 2023-10-13**，末收 **94.42** | ✅ **正確**——微軟併購完成日，貼近 95 收購價 |
| **SIVB** | 100 筆，但區間是 **2026-04-14 ~ 2026-09-04**，價格 **0.006** | ❌ **陷阱，見下** |
| **FRC** | `Invalid API call` | ❌ 未收錄 |

### ⚠ SIVB 是一個會製造假報酬的陷阱

回傳的 100 筆**完全不含 2023 年 3 月矽谷銀行倒閉那段**，而是破產後**仍在 OTC
交易的空殼**，價格 0.006 美元。崩潰前的 SVB Financial 約 267 美元。

**直接拿來用會注入一筆假的 −99.99% 報酬。**

**一般規則**：下市股的 ticker 可能被沿用或在 OTC 續掛。
**拿到資料不等於拿到正確的資料**——每一筆下市股價格都必須核對
「日期區間是否涵蓋它真正的交易期間」，不能只看「有沒有回傳」。

## 三、致命限制：免費層只給 100 個交易日

`outputsize=full` 是**付費功能**（實測回：「The outputsize=full parameter value
is a premium feature for the TIME_SERIES_DAILY endpoint」）。
免費層只有 `compact`＝**近 100 個交易日**。

**這代表什麼**：
- 775 檔下市股，每檔 1 次請求 → 以每日 22 次的保守預算，**要 35 天才抓得完**
- 而且抓完每檔**也只有 100 天**，不是完整歷史

**100 天不足以做回測。** 所以 Alpha Vantage 免費層**沒有補起存活者偏誤缺口**，
它證明的是「下市股價格原則上拿得到」，不是「我們拿得到足夠的下市股價格」。

## 四、另一個必須隨資料傳下去的限制

`TIME_SERIES_DAILY_ADJUSTED` 也是付費端點。免費層的 `TIME_SERIES_DAILY`
**未做除權息調整**。用於報酬計算前必須自行處理，
**不能默默當成調整後價格用**——這一點已寫進 `av_price_client.daily_prices()` 的
docstring 與回傳 note。

| 用途 | 可行性 |

| **下市股最後 100 天價格**（抽查用） | 🟡 可用但需逐檔核對日期區間（SIVB 陷阱） |

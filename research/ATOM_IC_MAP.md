# ATOM_IC_MAP.md — 原子.二 depth-1 表達式 IC 地圖（描述性掃描）

2026-09-20建立。對應`PENDING_QUEUE.md`「原子.二」、`TRIALS_LEDGER.md`
#285。**本檔案只出零件層級的IC分布統計，禁止指名「最佳素材」**——這是
總司令原文的明確禁令，任何看到本檔案的人不得把下方任何一行數字當成
「建議使用的因子」。

## 1. 事前登記的搜尋空間

| 類別 | 組成 | 數量 |
|---|---|---|
| (A) 窗口算子 × 原子 × 窗口 | 10個窗口算子（`delay`/`delta`/`ts_mean`/`ts_std`/`ts_max`/`ts_min`/`ts_rank`/`ts_sum`/`ts_argmax`/`decay_linear`）× 24個原子 × 4個窗口(1/5/20/60) | 960 |
| (B) 純量算子 × 原子 | 3個純量算子（`sign`/`abs`/`log1p`）× 24個原子 | 72 |
| (C) `ts_corr`(股票原子,基準原子,窗口) | 14個股票原子 × 10個基準原子（b50_o/h/l/c/v、btx_o/h/l/c/v）× 4個窗口 | 560 |
| **合計（depth-1表達式）** | | **1592** |
| × 2個horizon（20日/60日） | | **3184個測試** |

明確排除`mul`/`ratio`類原子×原子全排列組合——總司令原文的`mul`範例
（`sign(delta(c,1))×v`）本身是深度2用法，留給原子.三用已存活的深度1
素材去組，不在本輪depth-1掃描範圍內。

## 2. 執行方式

- 樣本：300檔（`sample_universe_ids(300)`），實際可用（有260天以上
  歷史且能成功計算全部1592個表達式）的股票數見下方第4節。
- 每個horizon各自建立snapshot序列（`build_snapshots()`），依
  `validation/holdout.py`的`TRAIN_END`/`VAL_END`切分TRAIN/VAL，
  **VAL不碰、holdout更不碰**——`is_holdout_consumed()`全程確認`False`。
- 每個snapshot對橫斷面（across當時可用股票）用`DataFrame.corrwith
  (method="spearman")`一次算出全部1592欄的cross-sectional IC，取代
  原本逐一expression×snapshot×stock三層迴圈（量級太大，約4400萬次），
  向量化後每個snapshot只需一次矩陣運算。
- 對每個表達式分別取TRAIN期snapshot的IC平均值與VAL期snapshot的IC
  平均值，回傳`train_mean_ic`/`val_mean_ic`/`n_dates_train`/
  `n_dates_val`/`same_sign`（TRAIN與VAL平均IC是否同號）。
- 15檔smoke test（`atom_ic_map_result.json`初版）先驗證邏輯正確
  （3184列數字合理）後，才跑300檔全量（本檔案分析的版本）。

## 3. 重大方法論發現：基準原子的「純轉換」分支結構性退化（不是bug）

**這是本輪最重要的發現，比任何單一IC數字都重要，因為它改變了如何
解讀整個搜尋空間。**

990個涉及基準原子（`b50_*`/`btx_*`）的表達式裡，**430個**是「window/
純量算子直接作用在基準原子本身，沒有結合任何個股原子」——例如
`delay__b50_o__1`、`ts_std__btx_c__20`。這類表達式在任一個snapshot
對**所有股票取值完全相同**：0050／大盤在某一天的（衍生）價格對每一檔
股票而言是同一個數字，跨股票橫斷面的變異數恆為零，Spearman相關係數
因此**數學上無定義**（多數snapshot回NaN，只有極少數因為forward-fill
邊界或缺值造成的巧合微小變異度而算出一個數字，那個數字是雜訊不是
訊號）。

**實測驗證**（本輪執行，非理論推導）：直接抽樣40檔股票查`atom_b50_c`
在同一天（2015-06-15）的值，16檔有資料的股票**全部回傳同一個數值
12.0177...**，零變異度，證實理論成立。

**影響範圍**：3184個測試中約**860個**（430個表達式×2個horizon）屬於
這種結構性退化，不是抓資料的bug（`_align_benchmark_field()`本身運作
正確，已用個股`2330`實測驗證：非空值範圍精確對齊0050基準資料的真實
可得範圍`2009-01-02`~`2024-12-30`）。**這860個測試仍然計入
`selection_bias_ledger`的N**（見第6節）——它們是事前登記、真實執行過
的測試，只是結果在方法論上無法產生cross-sectional訊號，計入N是保守
方向（讓多重比較校正更嚴格），不做任何事後排除的操弄。

**不受影響的560個`ts_corr(股票原子,基準原子,窗口)`表達式**（例如
`ts_corr__c__b50_c__20`）**沒有這個問題**——這類表達式算的是「個股
與基準的滾動相關係數」，這個係數本身**因股票而異**（有些股票跟大盤
連動性高、有些低），因此在橫斷面上有真實變異度，可以正常算IC。

## 4. 有效子集的描述性IC統計

有效子集＝602個純股票原子表達式＋560個`ts_corr`表達式＝**1162個表達式
×2個horizon＝2324個測試**（排除上述860個結構性退化的測試）。

| 統計量 | TRAIN | VAL |
|---|---|---|
| 平均IC | −0.0141 | −0.0086 |
| 中位數IC | −0.0035 | −0.0060 |
| 標準差 | 0.0447 | 0.0351 |
| VAL為正比例 | — | 41.7% |
| TRAIN與VAL同號比例 | 78.7%（1950/2324有效非空配對中） | |

**IR（資訊比率，IC均值/IC標準差）**：TRAIN約−0.32、VAL約−0.25——這是
**跨1162個表達式聚合**的統計量，用來描述整體搜尋空間的IC分布形狀，
不是任何單一表達式的IR，**不得誤讀成「這個空間有一個IR=-0.25的策略」**。

**質化觀察（非選材，只描述分布結構）**：horizon=60日的一群表達式
（波動度/真實區間類：`ts_std`/`ts_max`/`ts_min`/`decay_linear`
作用在`true_range`/`range`/`body`/`o`/`h`/`l`/`c`等原子上，約十餘種
操作化）呈現一致的負向IC（約−0.09~−0.13）且TRAIN/VAL同號。**這些
表達式彼此高度共線**（都是同一個底層概念「近期價格波動幅度」的不同
算子外殼），**不代表十幾個獨立發現，是同一個訊號的多種寫法**——經濟
機制上跟低波動異象（low-volatility anomaly）文獻方向一致，但這只是
質化觀察，不是本檔案的判定，判定需要等第5節的分年/牛熊段拆解完成。

## 5. 分年份與分牛熊段的穩定度分析（最終完成版）

**方法**：擴充`atom_ic_map.py`，用`REGIME_OVERLAY_PROTOCOL.md`第2節
既有的5個危機視窗（2011歐債危機／2015中國股災／2018Q4貿易戰／2020Q1
新冠崩盤／2022全年空頭，2008因早於資料起點2010-01-04完全沒有資料，
沿用本協定既有的排除規則，不是本輪新發明）當牛熊段標籤，對每個表達式
分別算「逐年平均IC」與「逐危機視窗平均IC」。快取逐snapshot的IC矩陣
成parquet（`atom_ic_snapshots_h20.parquet`/`atom_ic_snapshots_h60.parquet`），
`aggregate_by_year_and_regime()`直接讀快取聚合，不需要重新載入300檔
股票資料。

**⚠️過程中發現並修好一個真實的記憶體事故**：第一版全量跑（300檔）把
每檔股票「全部交易日×1592個表達式」都以float64常駐記憶體，實測單一
Python行程private memory衝到**18.9GB**，把使用者機器的可用記憶體從
31GB壓到剩1.26GB（互動視窗CC發現後手動kill該行程止血）。根因是
`indexed_exprs`字典存了每檔股票的完整歷史，但cross-sectional IC
計算實際只需要snapshot當下的as_of/fwd兩個日期。修法：先把兩個horizon
全部snapshot需要的日期算出聯集（185個日期，遠小於全部約3900個交易日），
每檔股票算完表達式後立刻reindex壓縮到這個聯集、丟棄其餘歷史列，
30檔測試驗證記憶體與正確性皆正常後，才重跑300檔全量（這次全程監控
記憶體，另掛一個「系統可用記憶體<3GB就自動砍行程」的安全閥）。

**結果（`TRIALS_LEDGER.md`#286）**：有效子集裡完整可比較的樣本
（`n_crisis_windows_with_data`=5，即5個危機視窗都有資料的表達式）
共**1950個測試**。全部5個危機視窗同號的比例僅**5.03%**
（horizon=20：4.62%、horizon=60：5.44%，兩個horizon一致），**低於
「5個獨立二元符號剛好全部一致」的樸素機率基準線6.25%**（=2×0.5⁵）。
疊加「train/val同號＋crisis同號＋逐年同號率≥0.7＋|VAL IC|>0.02」
四個條件同時成立的候選只有**15/1950（0.77%）**，遠低於單獨crisis
同號篩選在樸素機率下的期望值（約122/1950），這代表這15個不是訊號，
是大搜尋空間下的噪音殘留，且其中明顯有算子共線叢集（`ts_std`/
`ts_max`作用在`true_range`/`gap`上），不是獨立發現。

## 6. selection_bias_ledger 的 N 更新

- 本輪掃描前`TRIALS_LEDGER.md`列數（`selection_bias_ledger.parse()`
  回傳的row數）：**285**（含2026-09-20新登記的#284〈#72合規查證FAIL〉）。
- 本輪以**一筆consolidated條目**（`TRIALS_LEDGER.md` #285）登記整個
  3184測試的家族，**不是3184筆獨立ledger列**——比照「事前登記大搜尋
  空間、登記一筆標注家族大小」的既有做法。
- 登記後ledger實際列數：**287**（`parse()`實測值；註：`parse()`回傳
  287列但最大id為285，代表既有ledger本身存在2筆id重複的既有parse
  瑕疵，非本輪引入，不在本輪處理範圍）。
- **供Bonferroni校正參考的有效N**：287（ledger列數）+3183（本次
  3184測試家族扣掉已計入的1筆本身）=**3470**。
  `required_percentile(287)`=99.9826%；`required_percentile(3470)`=
  **99.9986%**——往後任何聲稱「通過多重比較校正」的候選，都要用
  3470（或屆時的最新累積值）當分母重算，不能沿用287。
- 分年/牛熊段拆解完成後另登記`TRIALS_LEDGER.md`#286（最終判定，
  延續#285同一個測試家族，不重複計入N）。

## 7. 分支結論

**日K原子層（depth-1）找不到穩定素材，判FAIL**（`TRIALS_LEDGER.md`
#286）。第5節的核心數字：全部5個危機視窗同號的比例僅5.03%，**低於**
「5個獨立二元符號剛好全部一致」的樸素機率基準線6.25%——牛熊段穩定度
不比純噪音更好，不是「偶爾有幾個候選看起來不錯但不夠多」的問題，是
整個depth-1搜尋空間（24個原子×19個算子的單層表達式）都沒有跨牛熊段
穩健的cross-sectional IC訊號。疊加多重穩定度條件後存活的15個候選，
數量遠低於樸素機率下的期望值，且彼此高度共線（同一個波動度概念的
不同算子外殼），不構成獨立發現。

**原子.三（depth-2/3組合）本輪不開工**——依規格「有素材進原子.三；
全部不穩定→誠實回報」，原子.三原本設計是「只用原子.二存活的深度1
素材去組」，現在沒有存活素材可用，這條路徑本身不成立，不是「暫緩」
而是「這個具體切入點走到底了」。

**不泛化聲明**：這只否決「這24個原子×19個算子的depth-1單層表達式，
用cross-sectional Spearman IC，20/60日horizon」這個具體搜尋空間，
不代表：(a) 更深的原子組合（`mul`/`ratio`/交互作用）沒有機會——那是
原子.三原本要測的不同假設，只是失去了「用depth-1存活素材當起點」這
條路，若未來要測需要重新設計比較基礎的搜尋策略（例如直接測某些有
明確經濟理由的深度2組合，不依賴depth-1篩選）；(b) 分K資料或其他頻率
的原子表達式沒有機會——本輪只測日K；(c) 個股層級的時序IC（非
cross-sectional）沒有機會——本輪只測橫斷面排序型IC。

# 資料誠實度盤點（里程碑 1）

依 `CONSTITUTION.md` 的鐵律「只用 point-in-time 資料、零未來函數；宇宙無存活者偏差」，實測 FinMind 免費方案在三個關鍵維度上的真實極限。**這份文件只記錄實測結果，不做樂觀推測**——沒測過的一律標「未測」，不是「應該可以」。

測試日期：2026-08-22。測試方式：直接 curl FinMind API，看真實回傳資料，不是看文件說明（文件跟實際行為不一定一致，之前已經在 openapi.twse.com.tw 上吃過虧）。

## 1. 還原股價（Split/除權息調整）

### 台股：`TaiwanStockPriceAdj`
```
curl "https://api.finmindtrade.com/api/v4/data?dataset=TaiwanStockPriceAdj&data_id=2330&start_date=2026-08-01"
→ {"msg":"Your level is free. Please update your user level...","status":400}
```
**免費方案完全拿不到還原股價**，不管帶不帶 `data_id` 都一樣被擋（跟期貨三大法人那種「帶對 data_id 就能免費用」的情況不同，這個是真的要收費）。

現在 App／資料管線用的 `TaiwanStockPrice` 是**原始未還原股價**。用實際除息案例驗證邏輯（非數字證據，因為單日漲跌幅度通常遠大於股息金額，光看價格差看不出來）：2330 在 2025-06-12 除息（`TaiwanStockDividend` 查到 `CashExDividendTradingDate:"2025-06-12"`、現金股利 4.5 元），但 FinMind 另外賣一個「還原股價」資料集這件事本身就證明：`TaiwanStockPrice` 不是還原股價，否則沒必要另外賣。

**影響：** 任何用免費 `TaiwanStockPrice` 算報酬率、回測績效的地方，除權息日前後的報酬會被污染（真實報酬被低估，因為除息當天的價格下跌會被誤判成虧損）。台股平均每年除權息一次以上，長期回測**必須**自己還原股價，或想辦法拿到 `TaiwanStockPriceAdj`（付費）或改用 `TaiwanStockDividend`（免費，見下方）自己還原。

**可行的免費替代方案：** `TaiwanStockDividend` 資料集是免費的，含 `CashExDividendTradingDate`、`CashEarningsDistribution`、`StockExDividendTradingDate`（股票股利）等欄位，理論上可以自己寫還原邏輯（在每個除權息日之前的價格，乘上調整係數）。**這件事還沒做**，只是確認了「素材都在，要自己組裝」。

### 美股：`USStockPrice`
```
curl ".../data?dataset=USStockPrice&data_id=NVDA&start_date=2024-06-05&end_date=2024-06-12"
```
NVDA 在 2024-06-10 盤後執行 10:1 股票分割。抓回來的資料裡，**分割前（6/5–6/7）的 `Close` 就已經是分割後的價格量級（約 $120，而不是分割前實際的約 $1200）**——代表 FinMind 美股資料在分割發生後有回頭把歷史價格改成還原後的數字。`Adj_Close` 另外還做了股利調整（跟 `Close` 有小差距）。

**結論：免費美股價格資料本身就是還原股價，不用額外處理。** 這是台股/美股資料誠實度上最大的不對稱，寫程式時要小心別把兩邊當同一種資料處理。

## 2. 存活者偏差（下市／下櫃股票）

### 下市清單：`TaiwanStockDelisting`
免費，回傳 723 筆（1995–2026），含股票代號、下市日期、名稱。年度分布：2000–2003 年是高峰（各 68–87 筆，應是當年台股本益比泡沫後的下市/整併潮），近年每年約 10–30 筆。**這份名單本身沒有付費限制，涵蓋期間夠長。**

### 下市股票的歷史價格是否還查得到？
這是關鍵測試——光有名單沒用，要能查到「牠們還活著時」的價格才能拿來做無偏差回測宇宙。三個抽樣：

| 股票 | 下市日 | `TaiwanStockPrice` 查得到歷史價格？ |
|---|---|---|
| 1230（聯成食品） | 2001-11-01 | ❌ 查無資料（空陣列） |
| 1408（中興紡織） | 2006-06-26 | ✅ 查得到（測了 2006 年初到下市前） |
| 00906（大華元宇宙科技50 ETF） | 2023-07-06 | ✅ 查得到，一路到下市前一天 2023-07-05 |

**結論：免費方案對「近代」下市股票（粗抓大約 2003 年之後）看起來有價格史，但更早的（測到 2001 年那筆）完全沒有。** 這代表：
- 如果回測範圍只涵蓋約 2005 年之後，用 FinMind 免費資料**理論上可以組出含下市股的無偏差宇宙**（名單 + 歷史價格都拿得到），但這點只驗證了 3 檔樣本，還沒有系統性驗證「2003 之後的下市股是否全部都查得到」，也還沒驗證更精確的分界年份在哪裡（只知道落在 2001–2006 之間）。
- 如果回測要往前推到 2000 年前後或更早，免費資料的存活者偏差問題會很嚴重，需要額外資料源。
- **這個結論優先度：中——因為 App 現階段的實際使用場景（近期選股/監控）不受影響，但未來做長期歷史回測前，必須先系統性驗證全部 723 檔的資料覆蓋率，不能只信這 3 個樣本。**

## 3. 財報 Point-in-Time（公布時點 vs. 所屬期間）

這是**最容易被忽略、也最危險**的一項——如果沒發現，回測會用「還沒公布的財報」去下單，數字會好看到不真實。

### `TaiwanStockFinancialStatements`（季報）
```
curl ".../data?dataset=TaiwanStockFinancialStatements&data_id=2330&start_date=2025-01-01"
```
回傳欄位只有：`stock_id / value / date / type / origin_name`。**`date` 是財報所屬季度的期末日（如 "2025-03-31"），完全沒有公告日期欄位。**

台灣上市公司公布 Q1 財報的**實際時間通常是 5 月中，Q2 是 8 月中，Q3 是 11 月中，年報+Q4 是隔年 3 月中**（依主管機關規定），跟期末日之間有 45 天以上的落差。**如果直接拿 `date`（期末日）當作「這天已經知道這些數字」去跑回測，等於是提早 1.5 個月看到財報，是嚴重的未來函數。**

**目前沒有在這份資料集裡找到解法。** 可能的路：
1. 另外抓 TWSE/公開資訊觀測站的「財報公告時間」清單，自己對應上去（還沒測試這條路是否可行、免不免費）。
2. 保守做法：所屬期間期末日 **一律加 45–60 天緩衝**當作「可用日」的下界近似值，直到真正拿到公告日期資料為止。這只是權宜之計，不是真解法，要在程式碼與文件上明確標注「這是近似公告日，不是真實公告日」。

### `TaiwanStockMonthRevenue`（月營收）
```
curl ".../data?dataset=TaiwanStockMonthRevenue&data_id=2330&start_date=2025-06-01"
```
比財報好一點：有 `create_time` 欄位。**但只有近期資料（約從 2026-04 起）的 `create_time` 有實際日期，更早的月份 `create_time` 是空字串 `""`。** 月營收的 `date` 欄位本身也不是公告日，而是「隔月 1 號」這種記錄日期（例如 2025-06-01 對應的是 5 月營收，實際上市櫃公司月營收要到隔月 10 號左右才公布——`create_time` 為 2026-04-21 對應 2026 年 3 月營收，跟法規的「次月 10 日前公布」大致吻合，可信）。

**結論：**
- **近期（約 2026-04 之後）的月營收有可信的真實公告時間戳，可以拿來做嚴謹 PIT 回測。**
- **更早期的月營收沒有公告時間戳，只能用「次月 10 號」這種規則近似**（跟財報一樣是權宜之計）。
- 這比財報季報好處理，因為月營收公告日期規則相對單純固定（次月 10 日前），財報公告日期則因公司而異、沒有這麼統一的近似規則。

## 4. 還沒測的項目（誠實列出，不要假裝測過）

- 除權息還原股價的「自己組裝」邏輯還沒寫，也還沒驗證組出來的還原價對不對。
- 723 檔下市股的歷史價格覆蓋率，只抽測了 3 檔，還沒系統性掃過。
- 有沒有其他免費資料源（如公開資訊觀測站 MOPS 直接爬蟲）能補上財報公告日缺口，還沒研究。
- 美股是否也有存活者偏差問題（下市美股名單、歷史價格），完全還沒測試（`USStockInfo` 目前只驗證了存在的公司，沒去查已下市/被併購美股）。
- 台股期貨/選擇權的還原、歷史深度、存活者偏差，都還沒測。
- 資料落地成 parquet 本地快取（避免每次重抓、也避免 FinMind 流量上限）——這件事在里程碑 2/3 建驗證框架與前測基礎設施時應該一併處理，現在只是先點出需求，還沒動手做。這個 Python 資料研究/回測管線目前還沒決定要放在哪個目錄（`alpha-data` 是凍結區、`alpha-app` 是純前端 repo），這是需要使用者決定的事，寫進 `STRATEGY_LOG.md`。

## 給下一步（里程碑 2：驗證框架）的提醒

在驗證框架的成本模型裡，除了鐵律裡列的手續費/證交稅/滑價，**「資料偏差」本身也要當成一種要揭露的成本**：任何在 2005 年前的台股回測、任何用到季報「期末日當公告日」的訊號，都要在報告裡標註「此結果可能因資料偏差而失真，僅供初篩」，不能當作乾淨的樣本外驗證結果。
